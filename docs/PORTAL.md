# AICV 포탈 설계 (2단계 — MVP 검증 후 착수)

취지: "지속 업데이트되는 AI 활용 능력 이력서" — MCP가 주기적으로 증거 팩을 올리면
포탈의 공개 프로필이 자동 갱신된다. 링크 하나(`aicv.example/r/<핸들>`)가 이력서가 된다.

## 포지셔닝

시장은 "많이 썼다"(Viberank·CCgather 리더보드)와 "시험 쳤다"(AIQx 자격증)로 갈라져 있다.
AICV는 그 사이의 빈 자리 — **실제 작업 로그가 역량을 증명한다**.

## 아키텍처

```
[aicv-mcp (로컬)] --증거 팩 JSON--> POST /api/evidence  (X-Upload-Token)
                                        │
                                   [서버 DB: 핸들별 최신 팩 + 스냅샷 이력]
                                        │
[채용담당자/공유 대상] <-- GET /r/<핸들>  (공개 프로필 페이지, SSR 1장)
```

- 업로드 페이로드 = 증거 팩 JSON 그대로 (schema_version으로 호환성 관리)
- 이력서 본문(호스트 LLM이 쓴 markdown)도 함께 업로드 가능 — 페이지 상단에 표시
- 스냅샷을 서버에도 쌓아 성장 그래프(주별 rubric 추이) 렌더링

## API (v1)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /api/evidence | 증거 팩 업로드 (토큰 인증). 같은 날짜는 교체 |
| POST | /api/resume | 완성 이력서 markdown 업로드 (format별) |
| GET | /r/{handle} | 공개 프로필 HTML (opt-in 공개 시에만) |
| GET | /api/me | 내 프로필·공개 설정 조회 |
| PATCH | /api/me | 핸들·공개 여부·표시 블록 선택 |

## 공개 프로필 페이지 구성

1. 헤더: 핸들 + 한 줄 요약 + "검증된 로컬 로그 기반" 배지 + 최종 갱신일
2. rubric 5축 레이더/막대 + 이전 스냅샷 대비 델타 화살표
3. 하이라이트 카드 (highlights 배열)
4. 성장 그래프 (스냅샷 시계열)
5. 스택·도구 환경, git 산출물 요약
6. 푸터: caveats 요약 (정직성) + "나도 만들기" CTA → MCP 설치 안내

## 프라이버시 (설계 원칙 그대로 승계)

- 서버는 증거 팩만 받는다 — 원문·경로 없음 (reveal_projects 팩은 업로드 거부)
- 프로필은 기본 비공개, 블록 단위 공개 선택 (예: 토큰량 숨기고 rubric만)
- 삭제 요청 시 스냅샷 포함 전체 삭제

## 구현 메모

- tokenbill 서버(FastAPI+SQLite)와 같은 EC2에 별도 컨테이너·별도 도메인으로 배포
  (코드는 이 레포, 브랜드는 분리 — core/ 공용)
- 인증은 tokenbill upload_token 방식 재사용하되 발급은 AICV 랜딩에서 별도로
